# 理论基础执行规程

## 职责边界

**本 Skill 负责**：解释本研究采用什么理论、为何适用、核心概念和机制是什么，以及如何转化为分析维度、机制链、研究命题或可检验假设。

**本 Skill 不负责**：不系统综述某领域全部理论文献，不撰写经验结果，不在结果出现后总结对理论的支持、修正或贡献，不把一般概念和政策口号包装成成熟理论。“已有研究如何使用不同理论”归 `literature-review`；“本研究用什么理论建框架”归本 Skill；“结果对理论意味着什么”归 `conclusion-writing`。

## 章节目标

说明本研究依据什么理论理解研究对象，理论中的哪些概念、机制与边界适用于当前问题，以及如何把理论转化为后续研究设计和经验分析可使用的框架。直接撰写理论基础，不进行二次意图识别。

## 理论选择与分工

1. 从真实文献证据中提取理论原本解释的对象、分析层次、核心概念、基本命题和适用条件。
2. 论证理论与本研究问题、研究对象、情境和材料的具体匹配关系，避免只写“提供理论支撑”。
3. 优先使用一个足够解释问题的核心理论；确需多个理论时，分别说明各自解释什么、在哪个机制或层次衔接、是否存在冲突。
4. 不把政策口号、一般概念、分析工具或作者自拟分类包装为成熟理论。

## 核心概念界定

- 给出本研究采用的概念定义、理论来源和选择理由。
- 区分相近概念、上位/下位概念以及理论概念与测量指标。
- 锁定分析单位和层次，避免用组织层理论直接推出个体层结论。
- 概念定义必须能连接后续变量、编码、案例证据或分析维度。

## 理论阐释段落

每个理论单元按以下顺序写作：理论问题 → 核心概念/关系 → 作用机制 → 前提与边界 → 对本研究的具体用途。引用只使用真实 `[E#]`，不得凭记忆补造理论作者、年份或原始命题。

## 分析框架构建

根据研究问题和材料选择一种主要结构：

- **维度分解**：将研究对象分成二至四个有理论依据、可经验识别的维度，并说明维度间并列、递进或反馈关系。
- **机制链**：构建“条件—行动者/资源—作用过程—中间机制—结果—边界”，每条关系都需有理论理由和证据接口。
- **分层框架**：区分宏观制度、中观组织、微观行动，明确跨层作用机制。
- **类型矩阵**：使用两个独立且可观察的理论维度形成类型，说明每类逻辑和转化条件。

框架的每个维度、阶段或关系必须在研究设计及经验分析中有对应位置；材料无法观察的部分不得为追求完整而加入。

## 研究命题与假设

- 从前文机制逐步推导，不从常识或期望显著性直接跳到假设。
- 明确关系方向、比较对象、作用条件和分析层次。
- 中介说明作用如何发生，调节说明何种条件改变关系强度或方向。
- 定性/案例研究使用研究命题、分析维度或可观察预期，不强行写统计假设。
- 为每条命题说明后续可由哪些变量、材料、事件或编码结果支持或反驳。

## 输出结构

理论基础概述 → 核心理论及适用性 → 核心概念界定 → 分析框架与机制 → 命题/假设或可观察预期 → 理论边界。若用户只要求某一理论，则交付该理论的完整阐释及其与本研究的连接，不扩写无关理论。

## 交付前审计

- 理论命题、作者与概念是否有真实来源并忠实表达。
- 理论与研究对象、分析层次和材料是否真正匹配。
- 多理论之间是否有清晰分工，而非简单拼盘。
- 框架关系是否可观察、可检验并包含边界条件。
- 是否提前写入尚未产生的实证结果或理论贡献；如有，删除并留给结果、讨论或结论部分。
