# 分阶段交付规则

## 从零开始

先交付研究蓝图，不直接写完整论文。研究蓝图至少包括：暂定题目、研究对象与边界、研究问题、可能的研究路径、章节或文章逻辑、现有材料、证据缺口和下一步建议。

研究问题、材料或方法尚不明确时，基于现有上下文完成可支持的蓝图，把不确定部分标为待补，不暂停为通用问卷。

## 已有草稿续写

1. 概括已写部分的中心主张、证据和未完成的衔接点。
2. 明确下一小节的任务及其与前文、后文的关系。
3. 只续写用户指定的小节；保持术语、时态、引文格式和论证强度一致。
4. 若草稿中存在与新指令冲突的结论，不静默改写；保留原结论并说明冲突影响。

## 明确小节写作

可以直接写作的最小条件：用户已给出小节位置或功能、材料范围或可接受的概念性写法、目标字数/篇幅，且没有会改变论证方向的未决问题。

写作前简要给出：小节主张、段落安排和所需证据。用户要求直接出稿时，可将这三项压缩为一两句说明后进入正文。

## 长篇请求

整篇、整章或大篇幅正文按以下顺序推进：

1. 论证图：章节目标、每节问题、主张与证据关系。
2. 单元选择：依据用户本轮要求确定优先小节；未指定时选择证据最充分、最能推进论证的一节。
3. 单元草稿：每轮只完成一个逻辑闭合的小节或约定字数。
4. 整合审校：检查小节之间的重复、跳跃、术语不一致和证据缺口。

## 润色与诊断

润色不改变原文中的事实、研究设计、结论强度或引用信息。直接依据用户本轮意图处理学术表达、逻辑衔接、段落结构、引文规范或投稿风格，然后输出修改稿，必要时附带关键修改说明。

需要进行细粒度检测时，使用 `scripts/writing_scanner.py` 生成报告；不要让脚本自动替换用户文本。
