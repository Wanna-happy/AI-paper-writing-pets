# 已有草稿的接续与完善

## 草稿映射与续写

在内部建立“草稿地图”，随后直接完成用户指定的续写或修改目标：

| 项目 | 识别结果 |
| --- | --- |
| 已完成单元 | 章节/小节及其承担的论证任务 |
| 已有主张 | 每节中心判断与结论强度 |
| 已有证据 | 文献、数据、引语、案例或待核验来源 |
| 断裂与重复 | 前后文衔接、概念不一致、重复表述 |
| 下一单元 | 最小可完成的续写或修改任务 |

明确区分：用户已经写出的事实、用户已确认的研究设计、草稿中的无来源断言、以及需要用户补充的内容。

## 续写流程

1. 定位上一段/上一节的结尾主张。
2. 说明下一单元的功能：承接、展开、转折、比较、解释、收束或进入下一章。
3. 从用户要求和草稿中确定本轮写作范围与可用证据。
4. 只生成目标单元，并让结尾为下一单元留出明确接口。
5. 标出需要核验或补充的内容，避免把缺口埋进正文。

## 常见修复路径

- **引言只有背景**：补出文献脉络、具体缺口、研究问题和贡献，而不是再添加宏观事实。
- **文献综述是摘要串**：按理论争议、对象差异、方法差异或解释不足重组，并在每组末尾连接本文。
- **方法过于笼统**：补齐对象、样本/文本范围、材料来源、步骤和质量/伦理信息；没有真实信息时列出需补材料。
- **结果堆数据或引语**：逐段增加解释句，明确材料与主张的关系，并检查反例/边界。
- **讨论重复结果**：转向“结果与既有研究的异同、机制含义、边界、可迁移条件”。
- **结论只重复摘要**：回收研究问题，按发现、贡献、局限和未来问题收束。

## 改写边界

除非用户明确授权，不改变研究问题、样本、数据、引用、统计结论和事实性叙述。遇到错误或冲突，保留原信息，提供“问题—影响—建议处理”，并继续完成不受冲突影响的部分。
