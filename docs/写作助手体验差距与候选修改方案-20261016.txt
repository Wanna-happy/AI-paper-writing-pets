日期：2026-10-16
状态：供用户选择；本轮未修改产品业务代码，未执行下列候选方案。

一、结论与产品定位

主要差距在于：已有能力分散在对话、弹窗、右侧预览和项目资料中，用户还要自己寻找当前稿、确认修改结果、判断任务是否真正完成。
优先目标应是让用户清楚“当前在改哪一稿、改动是什么、是否保存、下一步能做什么”，同时保证研究任务可以可靠延续。
保留本产品的优势：本地项目资料、引用证据回溯、数据清洗与真实分析产物、研究方案确认、断点恢复、论文组装与宠物陪伴。无需把产品改成通用聊天工具或完整 Office。

三、用户旅程健康度

步骤1：创建项目、接入模型——可用，但新建表单偏长，设置暴露较多技术项；需要降低初次使用负担。证据 S2/S6。
步骤2：导入、查找资料——已有导入、资料名/备注搜索与本地索引；资料管理偏文件清单，需要加强学术检索和组织。证据 S3 与 renderLibrary。
步骤3：提出任务、确认方案——已有明确的确认及修改入口、右侧方案；真实模型是否稳定继承意图与已确认进度待验收。证据 S7/历史用户反馈。
步骤4：执行与恢复——已有进度、过程记录、错误收尾和恢复机制；长链路可靠性未在本轮实测，健康度待确认。
步骤5：阅读、修改草稿——已有右侧预览、选区操作和引用片段；编辑路径分散，局部改写直接应用，用户控制感不足。证据 S1/S4/S5/S7。
步骤6：导出、回访项目——已有 Word 导出、论文组装、草稿保存和运行断点；缺少明显的稿件版本/成果集中管理入口。证据 S1、当前前端入口及 thesis-controller。

五、候选修改项（可独立选择编号）

标记说明：
【已确认】当前界面/代码可直接支持判断。
【待验证】历史曾发生或存在风险，本轮未用真实模型重现；先验证再决定修复。
【增强】新增产品能力，不应描述成现有功能故障。
P1：建议优先；P2：第二阶段；P3：可选。S/M/L 是相对工作量，非工期承诺。

UX01｜统一草稿工作区及入口｜P1｜L｜已确认
现状：同一草稿有查看链接、文件入口、查看与修改正文、导出 Word、引用核验等入口；查看与修改正文打开模态窗，右侧另有 paper 预览。用户必须理解多个入口差别。S1/S4/S7；openDraftEditor/openPaperPreview。
修改：以右侧文稿为持续编辑位置；对话只给短结论和一个主文件入口；编辑、引用、导出、版本放入该文稿工具栏。保留查看源资料与原有导出能力。
验收：从历史对话、成果列表、文件链接打开同一草稿时显示同一内容版本；关闭重开可恢复位置；一个文稿的不同入口不产生不同副本。
依赖：先定义统一文稿标识及版本标识；和 UX02/03 共用数据契约。

UX02｜改写先预览，再接受或取消｜P1｜M｜已确认
现状：applyLocalSkill 返回后立即替换选区并保存，之后才显示“本次改写对比”；对比主要是修改前后整段文本。S5。
修改：先展示差异和修改理由；用户可接受/拒绝；提供撤销本次应用。引用、数字和术语发生变化时能明显看出。
验收：拒绝不改变稿件；接受只改变选区；撤销后内容与引用恢复；应用时若原稿已变更，提示重试而非覆盖新内容。
依赖：至少建立一次修改前快照；无需等待完整历史界面。

UX03｜稿件版本、比较与恢复｜P1｜L｜已确认的前端缺口
现状：有草稿保存、方案 revision 和任务断点，但检查到的稿件界面没有面向用户的完整历史版本列表/恢复入口。这不等于底层完全没有历史记录。
修改：生成正文、接受改写、手动保存形成可识别版本，记录来源与时间；可比较、命名、恢复为新版本。任务恢复与稿件版本分开表达。
验收：连续修改三次后可找回第一次；恢复保留后续历史；重启仍可比较；删除、迁移、存储上限遵循同一保留规则。
依赖：统一稿件标识、不可变快照和数据迁移策略。

UX04｜项目成果与章节导航｜P1｜L｜已确认的可发现性缺口
现状：主导航是新建对话、资料库和对话列表；草稿入口依附消息；后端已有论文控制和组装，缺少可见的章节/成果总览。S1，thesis-controller。
修改：增加项目成果页或侧栏页签，按文稿、表图、数据副本分类；长论文显示大纲、各章当前稿和字数，支持跳转、标记定稿与选择组装来源。
验收：不用翻历史消息就能找到最新章节；区分上传原件和生成文件；组装前显示实际使用的版本与缺章。
依赖：UX01 稿件标识；引用现有论文控制，不重造固定论文流程。

UX05｜“继续”与动态规划可靠性验收｜P1｜M 起｜待验证
现状：历史截图反复出现已确认仍被追问、下一步不能承接、方法没有执行路径；当前已有意图/规划/恢复实现。截图不能证明最新实现仍失败。
方案：建立真实模型验收集，覆盖普通问答、局部修改、清洗后分析、已批准方案继续、运行中补充、断点恢复、替换数据和跨对话隔离。失败后再定位提示词、上下文、调度或能力注册哪层出错。
验收：记录任务理解、计划、执行者、工具结果和产物标识；已完成步骤不重复跑；数据/方法变化时才重新确认相关范围；用户无需反复输入继续；无产物不得宣称完成。
依赖：用户选择实施后使用获授权且可用的模型配置。保持现有 harness，根据每轮目标规划，不固定“采集—清洗—分析—写作”四步。

UX06｜阶段反馈与失败后的下一步｜P1｜M｜待验证/体验增强
现状：已有过程折叠、阶段汇报、错误格式化和恢复；用户历史反馈说明“实际做了什么”曾不清楚，本轮只检查静态状态。
修改：统一阶段消息为“完成的工作/有依据的发现/产物入口/接下来做什么”；失败时列出保留成果与未完成项；恢复操作留在对应消息。内部规划仅在过程详情中按需查看。
验收：成功、取消、余额不足、网络中断都能收尾；过程默认折叠仍可展开；完成项与产物记录一致；不让模型补造失败后结论。
依赖：沿用已有事件和产物记录；先跑 UX05 场景，避免再次只改展示文案。

UX07｜资料库走向可管理的文献库｜P2｜L｜已确认/增强
现状：资料筛选主要搜索文件名和备注；主页面强调 RAG、分块、索引等实现概念。尚不是围绕作者、年份、研究主题、引用使用情况组织的入口。S3，renderLibrary。
修改：正文内容检索、作者/年份/主题筛选、标签及来源类型；添加文献元数据校正与去重；保留现有本地证据检索。将技术状态改为“可用于写作/解析中/需处理”，高级详情再展示索引。
验收：文件名不含关键词但正文包含时能找到；结果可定位片段；元数据可纠正；扫描件解析失败有可操作提示；不把未核验的联网结果自动当可信来源。
依赖：现有索引和来源身份；元数据/DOI 获取能力另行评估，首版可手动校正。

UX08｜引用核验从单条查看变成问题清单｜P2｜M/L｜增强
现状：已能追溯 E 编号、页码与证据片段。差距是缺少清晰的“哪些引用还要处理”的集中工作方式；不能据此断言当前引用生成错误。S4。
修改：按“出处缺失、元数据不全、原文支持待核对、格式待统一”展示问题；点击定位正文和来源；标记用户已核验。文献有效不等于支持当前论断，两种核验分开。
验收：每个问题都指向具体位置和判断依据；可人工纠正；修订后状态更新；不宣传无法证明的全自动真实性保证。
依赖：UX01 文稿定位；UX07 可校正来源元数据。

UX09｜新手入口与任务范围提示｜P2｜M｜已确认
现状：新项目默认硕士论文；项目表单长，学科选项换行紧，长论文信息需要滚动；输入提示仍较通用。S2/S1。
修改：先填名称与任务类型，项目细节渐进补充；已有稿件可直接从“修改现稿”开始。用一句简短提示说明本轮会处理的对象，复杂任务才展示关键确认。
验收：只填必要信息即可开始；短任务不强迫填完整论文档案；不同项目类型默认字数合理；保留用户主动填写详细目标的入口。
依赖：不改变规划框架；依赖现有项目/任务状态做上下文提示。

UX10｜模型设置简化与故障自助｜P2｜M｜已确认/增强
现状：服务商、模型、base_url、密钥以及 Agent 独立配置集中在长设置页；模型占位文字仍提“中转站”，与本期已移除自定义中转站入口的方向不一致。S6/HTML。
修改：默认只展示服务商、模型、密钥和连接状态；地址与 Agent 独立设置放高级区；保存/连通/工具能力分别显示；错误提供对应的检查或设置入口。清理旧占位文案，不恢复中转站接口。
验收：不懂 Agent 的用户能完成共用配置；能分辨未保存、已保存未测试、可连接；连接成功不被当成所有分析工具均可用；界面与日志不暴露密钥。
依赖：沿用现有 provider registry 与安全存储。

UX11｜统一文件阅读工具及复杂格式验收｜P2｜M 起｜增强/待验证
现状：右侧点击、缩放和连续滚动已经补齐，不列为缺失。仍需检查读长文时的定位、搜索、缩放记忆，以及复杂 DOCX/大表的边界。
修改：按格式提供合理导航：文档目录/页码定位、PDF 文内搜索、表格单元格定位；共用缩放位置、键盘操作、加载/错误提示；保留上传文件只读、生成稿可编辑的权限差异。
验收：上传/生成、聊天附件/资料库/结果链接形成同一测试矩阵；中文字体、合并单元格、多工作表、大文件和窄窗口均验收；全部内容可到达且无截断；不承诺浏览器复刻所有 Office 功能。
依赖：现有预览组件；测试失败先修底层，再加导航增强。

UX12｜导出前检查和交付清单｜P2｜M/L｜增强
现状：已有 Word 导出、引用与篇幅检查和论文组装。需要把已有检查集中到用户交付动作，而非仅分散在回复和底层规则。
修改：导出前显示使用稿件版本、篇幅、缺章、待核验引用和表图；可跳转修复；提供学校/期刊格式预设作为后续选配。
验收：用户确认导出的版本与编辑界面一致；目录、脚注、表图编号专项验证；未通过项可见，允许明确选择带提示导出；不再让用户靠猜判断是否定稿。
依赖：UX03/04/08。先复用现有检查，模板库可单独排期。

UX13｜可访问性与操作细节｜P2｜S/M｜部分已确认、其余待验证
现状：有语义按钮、部分 aria 标签、快捷键和预览分栏键盘支持；草稿行次级操作视觉较弱，新项目学科词语断行。尚未进行屏幕阅读器或完整对比度测量。S1/S2。
修改：可点击/禁用态可区分，按钮热区统一；改写操作可由键盘触发；弹窗焦点返回；缩放至 200% 时主要控件仍可达；减少技术术语与重复入口。
验收：完整键盘走完创建、附文件、预览、选区改写、取消、导出；焦点可见且不丢失；对比度测量后再判断合规，不凭截图宣布 WCAG 通过。
依赖：跟随 UX01/02 的组件整合执行，避免两次重做样式。

UX14｜本地项目备份与迁移入口｜P3｜M/L｜增强
现状：本地保存与运行恢复已有；本轮前端未见明确的用户级项目备份/迁移流程。模型断点恢复不能代替设备损坏后的备份。
修改：可导出项目备份包并恢复副本，列明包含资料、稿件和结果，不包含密钥；恢复前校验版本和文件完整性。
验收：新环境恢复后引用与成果链接可用；不覆盖同名项目；不导出模型凭据。云同步与团队协作单独评估，不默认加入本期。
依赖：统一项目文件清单和稳定标识。

六、建议用户选择的实施组合

组合 A：先保证改稿顺手——UX01 + UX02 + UX03。
收益：统一阅读编辑入口，AI 改动可决定、可反悔。适合当前最频繁的写作与修改体验。
最小切片：先做 UX02 的预览/接受/取消与单次撤销，再统一编辑入口，最后补完整版本界面。

组合 B：先保证任务能顺利做完——UX05 + UX06。
收益：解决重复继续、错误收尾与真实交付可信度。先验证后修，避免把历史问题再用提示词掩盖。

组合 C：让论文项目长期可管理——UX04 + UX07 + UX08 + UX12。
收益：章节、资料、引用和导出衔接；适合长论文。依赖基础文稿身份与版本，建议在 A 后分批做。

组合 D：打磨易用性——UX09 + UX10 + UX11 + UX13；UX14 可独立选。
收益：降低新手成本、统一阅读操作、照顾键盘和高缩放使用。可按影响单项推进。

建议顺序：先选 B 做可靠性基线，同时做 A 的最小切片；随后完成 A，再决定 C/D。不是建议一次全部实施。

七、实施边界与共同验收

1. 保留现有 harness、主 Agent 动态规划、子 Agent 与 skill/工具分派，不固定完整论文流程。
2. 每次只执行用户选定编号；对共享目录先记录当时改动，不回滚其他对话的工作。
3. 新界面适配已有真实产物和历史数据，不改动原始上传资料，不生成虚假进度或模型结论。
