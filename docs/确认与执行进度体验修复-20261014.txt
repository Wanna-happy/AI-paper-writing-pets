确认与执行进度体验修复
日期：2026-10-14

截图问题与修改方案

1. 聊天回复超过一定长度就被自动折叠。
原因：通用 Markdown 渲染器设置了超过 850 字自动插入“展开完整说明”。
修改：移除按字数自动折叠的逻辑，保留完整正文、标题、列表和文件链接。

2. 右侧方案文档预览也出现“展开完整说明”。
原因：预览和聊天共用同一个渲染器，错误套用了聊天折叠规则。
修改：右侧文档连续展示全文，通过正常滚动阅读；原有编辑方案功能保留。

3. 确认方案后，用户消息自动填入整段研究问题。
原因：确认按钮使用“确认分析方案：研究问题全文”作为新任务。
修改：按钮只发送并展示“确认方案并分析”或“确认方案并写作”；方案 ID、版本和操作类型仍通过独立结构化参数传入，后端继续精确校验。
历史原始消息不批量改写。

4. 执行回复重复出现已确认方案的入口和确认按钮。
原因：每次刷新方案状态都会把同一个入口移动到最新回复，批准请求发出后还有短暂的旧状态窗口。
修改：入口绑定项目、对话和方案版本，留在原回复；确认请求发出后立即隐藏确认操作，批准后的新执行回复不再承接旧入口。
新保存的方案提交消息记录文档归属，刷新历史后也能定位到原回复；未提交方案的执行消息不产生该归属。
兼容旧消息时不猜测文档归属，不把已批准方案自动挂到最新回复。

5. 任务卡显示完整技术段落，其他步骤默认折叠。
修改：默认展开任务列表，每项使用简短名称和状态；较多任务允许列表内滚动，避免挤占整个输入区。
正常待执行项不重复显示依赖段落；失败等必要状态保留简短说明，完整执行记录仍可查看。
用户主动收起列表的选择在后续状态刷新中保留。
简单对话原有的任务卡显示门槛保持不变。

6. 原方案“第3步”被当成本轮 Agent 执行的第三项。
修改：按本轮真实任务列表独立编号，示例“执行任务 1/4 · DTW-K-Means 轨迹聚类”；列表为 1、2、3、4。
原研究方案编号仍保留在方案文档。精简只用于界面，不截断实际任务指令、算法、约束或参数。

补充：子 Agent 提示词明确不向用户回显 revision、pending-confirmation 等内部字段；修正方案提交工具中“方案卡在输入框上方”的过时说明。
