Agent 主干与分支规范（2026-10-13）

一、统一主干
校验项目/对话/附件归属 → 加载项目设置、当前用户输入、对话记忆和有效方案 → 独立意图识别 → 必要澄清 → 任务规划 → 校验角色/任务依赖 → 按分支装配技能和工具 → 子 Agent 执行 → 按产物类型校验 → 保存交付与运行记录 → 接受反馈。

意图识别不执行工具、不生成正文、不输出任务 DAG。信息足够后才调用任务规划。需要澄清时，主控保存最多两个必要问题并结束本轮，不启动子 Agent；用户回答后重新识别本轮意图。既有项目设置、历史已确认条件和已回答问题不得重复询问。读取文件才能确定的信息留到工具核验，不要求用户代替程序查看字段；依赖缺失属于环境处理，不属于要求用户放弃指定方法的理由。

二、分支与职责
1. 普通问答/概念解释/工作回顾/进度：conversation → 对话 Agent。可以读取本对话历史和技能指导。输出聊天消息，不创建正文草稿、不计算、不提交分析方案、不安装依赖。
2. 文献检索/来源核查/草稿评审/大纲：research → 对话 Agent。按需调用当前项目 RAG、历史和技能指导，输出来源、评审意见或大纲。没有联网搜索工具时不能宣称检索了外网或核实 DOI。评审建议不能自动成为改写后的正文。
3. 数据读取/字段/缺失/描述统计：inspection → 对话 Agent + inspect_data_file。核验实际工作表、筛选范围和统计量。遇到必须由用户确定的编码再追问；不能从该分支调用回归、检验或提交分析方案。用户新增建模要求时重新识别进入分析分支。
4. 安装/核查依赖：environment → 对话 Agent + 受控依赖工具。只核查或安装所需包，不读数据、不执行模型；成功不代表分析已执行，失败如实报告。
5. 新分析/修改分析：analysis → analysis-proposal。对话 Agent 核验实际数据、复用已有研究要求、提交具体方案，等待用户确认。执行方案只能来自产品确认入口，模型不能自行批准。
6. 分析并写作：mixed → 同样先进入 analysis-proposal。分析确认 → analysis-execution → 结果审阅 → writing-proposal → 写作确认 → writing-execution。不得用一个分析→写作 DAG 跳过两次确认。
7. 普通撰写/润色/重组：writing → 写作任务 DAG。允许对话角色承担仅限研究检索的前置任务，再将真实证据交给写作角色；逐任务限制工具，不能借此执行分析或安装依赖。流式输出正文 HTML，经过篇幅、证据、引用及格式检查后保存草稿。旧分析方案不会拦截与其无关的章节写作。
8. 依据当前分析结果写作/修改实证正文：writing 且 usesAnalysisResults=true → writing-proposal。确认标题、章节、篇幅和采用的已完成结果。批准后才能 writing-execution，写作不能重算分析。
9. 编辑器选区润色/扩写：明确 UI 操作直接进入现有 local-edit；只修改选区，保持引用与选区外正文，不启动整篇研究或分析流程。
10. 导出/排版：沿用现有编辑器和导出功能。技能中的 LaTeX/Shell 等名称不授予新工具能力，不擅自生成另一个工程。

三、分析与写作的确认状态
分析方案 pending-confirmation → 用户确认 approved → 每个已确认步骤执行 → results-review。
分析反馈修改模型、变量、样本或图表 → 新 revision 的 pending-confirmation → 再次确认；旧 revision 或数据指纹变化不能执行。
结果用于正文 → writing-confirmation → 用户确认 writing-approved → 正文生成和校验 → completed。
部分分析失败：保留已完成的真实结果与错误，不伪造其余步骤，不自动写正文。修改方案需要重新确认。

四、工具与 DAG 边界
分支、角色和工具限制由 electron/agent/flow-policy.js 校验，提示词只能细化职责，不能扩大权限。
工具装配之后按分支过滤：对话不能调用执行工具，分析提案不能 run_data_analysis，分析执行不能调用正文工具，写作执行不能安装包或重新分析。
执行前拒绝空任务、重复 ID、未知角色、超出分支的角色、自依赖、缺失依赖及环形依赖。任务与分析方案统一最多18步。上游任务必须完成后才向下游传递真实产物。
技能按项目学科、当前目标和步骤按需选择，引用通过只读工具分页加载。历史记忆不替代来源证据；外部技能不自动获得脚本执行权。每个执行角色接收项目题目、目标、学科、语言和引用设置；当前用户要求优先。普通问答不附带项目文件正文；其他任务只选择本轮明确附件或任务指定的材料，已索引文献通过RAG读取。英文按词数、中文按汉字计量。

五、恢复与异常
断点恢复：绑定存档原项目、原对话及已确认方案版本，拒绝跨对话恢复。读取存档 DAG、已完成产物和中断文本；已完成步骤不重跑。恢复不让模型重新批准方案，补充说明不能绕过既有统计口径和版本检查。
暂停/取消：停止新增子任务；部分流式文本不作为完成稿保存，断点保持可恢复。
无 API：聊天说明配置缺口并保存状态，不创建“论文草稿”假交付。
意图识别输出无效：进入澄清，不能默认写作。真实接口、鉴权或网络失败：停止本轮并保存错误，不把技术故障变成要求用户回答研究问题。模型请求取消继续传递取消状态。
任务规划输出无效：保守返回对话，不自动增加分析或正文权限。
工具失败：显示真实错误；分析结构错误或缺少实际结果不能当作完成。
正文未通过证据检查：拒绝保存完成稿；篇幅修订与代码修复保留现有有限重试机制，其他质量提醒不宣称已全部自动修复。

六、记忆与验收范围
保存原始对话、草稿、方案、结果和运行状态；后续轮次按当前对话压缩历史，近期用户要求优先。尚未新增跨项目偏好库或自动模板学习。
意图和角色判断仍由模型完成，可能误判；代码限制用于阻止误判扩散成跨分支执行，不能保证任何任务永不出错。
